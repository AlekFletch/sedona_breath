# Sedona Breath Lite: Huawei Watch Fit 4 и Fit 4 Pro

Версия приложения для **lite wearable**, то есть часов на LiteOS. Такие часы запускают только JS-приложения (HML/CSS/JS, FA-модель). Это отдельный проект DevEco внутри репозитория. ArkTS-версия из корня репозитория на эти часы не устанавливается.

Что Fit 4 Pro относится к lite-часам, подтверждено на устройстве (прошивка 6.1.0.117, API 6.1.0(23)). Там же проверены установка, ограничения памяти и движка. Использовались приложения RepPulse и BreathTrainer того же автора; ниже они упоминаются как «проверено на часах».

## Чем отличается от ArkTS-версии

| | ArkTS (корень репозитория) | Lite (эта папка) |
|---|---|---|
| Устройства | `wearable` (Watch 5, Ultimate…) | `liteWearable` (Watch Fit 4 / Fit 4 Pro и др.) |
| UI | ArkUI | HML + CSS + JS |
| Логика сессии | `entry/src/main/ets/core` | **та же**, сгенерирована в `core/*.js`; вопросы проходит `common/promptFlow.js`, сверенный с ядром тестами |
| Строки | `resources/{base,en,es}` | **те же**, сгенерированы в `i18n/*.json` |
| Вибрация | импульс 50 мс, длинный 800 мс | системные `short` и `long` (≈1 с); остановить уже идущую вибрацию нельзя |
| Хранение | Preferences + RelationalStore | JSON-файлы `internal://app/*.json` (`@system.file`) |
| Health Kit | пульс по согласию | нет |
| Быстрый старт 3 мин | карточка на часах | кнопка «Быстро · 3 мин» на главном экране (карточек на lite нет) |
| Язык | системный + ручной выбор | системный + ручной выбор, применяется сразу |

Экраны и сценарий те же (11 экранов). Онбординг с дисклеймером → главный экран → настройка → вступление → дыхание и вопросы → выбор эмоции (в полной практике) → завершающее дыхание → оценка 1–5 → сообщение → итог → «Сохранить». Прерывания работают так же: «Продолжить» / «Завершить сейчас» / «Завершить и сохранить». Если система выгрузила приложение, на главном экране появляется «Практика не завершена».

## Как устроено: память часов

На часах около 100 КБ JS-кучи. Lite-рантайм держит в ней одну страницу, кроме момента перехода: тогда в куче лежат и старая, и новая. Отсюда правила, которые проверены в симуляторе (см. ниже):

- **Страницы ничего не делят в памяти.** `this.$app.$def` в lite нет, а `app.js` пустой. Каждая страница создаёт свои объекты и читает файлы. Между страницами данные передаются через файлы (`settings.json`, `history.json`, `snapshot.json`, `pending.json`) и параметры `router.replace`.
- **Сессия разделена на две страницы.** `pages/session` — вступление, дыхание и завершающее дыхание. `pages/prompt` — вопросы, эмоция, оценка и сообщение. Когда шаг меняется, страница пишет снимок `SessionController` и открывает другую страницу, а та восстанавливает снимок и сразу продолжает (`common/sessionPage.js`). Целиком сессия требует около 106 КБ кучи, после разделения каждая страница укладывается в 95 КБ.
- **На странице вопросов нет полного `SessionController`** с движком дыхания. Её шаги проходит `common/promptFlow.js`, построенный на `SessionPlanner` и `SupportRules` из ядра. `tools/node-test/lite.mjs` прогоняет одни и те же практики через оба и сравнивает каждый снимок, вид и запись.
- **Строки не входят в JS.** Файлы `i18n/{ru-RU,en-US,es-ES}.json` одинаковые и содержат все три языка. Страница получает текст через `$t('<язык>.<ключ>')`, поэтому язык из настроек применяется сразу. `i18n/<страница>.js` содержит только список ключей шаблона.
- **Страницы сессии не читают настройки:** язык, ритм и вибрация приходят в параметрах (`Store.sessionParams`). Итог открывается, пока сессия ещё в памяти, поэтому он тоже лёгкий.
- **JS минифицируется в debug-сборке** (`tools/minify-lite.mjs`, задача `SedonaMinifyLiteJS` в `entry/hvigorfile.ts`). Часы не открывают страницу больше 48 КБ, а release-пакет DevEco Assistant не ставит. Используется только `mangle`: `compress` ломает загрузчик. Скрипт печатает размеры страниц и падает на тех, что больше 48 КБ.

Особенности lite-движка (проверено на часах и в симуляторе):

- **Регулярных выражений нет.** Часы компилируют каждый `.js` в байткод при установке, и регулярка роняет установку с ошибкой 34. `tools/build-lite.mjs` проверяет это во всех lite-файлах.
- **Иконка.** Она должна называться строго `$media:icon`, и рядом должен лежать `icon_small.png`, иначе ошибка 40.
- **Длинная цепочка `if`/`elif` не рисуется:** четвёртый `elif` давал чёрный экран. Блоки экранов сделаны отдельными `if` по одной переменной `screen`.
- **`prompt.showToast` перед `router.replace`** не даёт странице уйти.
- **Методы страницы не называются `render`:** загрузчик кладёт туда шаблон.

## Единый источник правды

Ядро и строки **не редактируются вручную**: их генерирует `tools/build-lite.mjs` из ArkTS-проекта.

```bash
# пересобрать core/*.js и i18n/* после изменений в entry/src/main/ets/core или в строках
node tools/build-lite.mjs
```

```bash
# проверить, что сгенерированные файлы актуальны и в lite-JS нет RegExp (для CI)
node tools/build-lite.mjs --check
```

Вручную написаны:

- `common/store.js` — настройки и `Store` для страниц вне сессии;
- `common/strings.js` — тексты через `$t`;
- `common/records.js` — снимок и запись, ожидающая итога;
- `common/history.js` — история;
- `common/sessionPage.js` — общая часть двух страниц сессии;
- `common/promptFlow.js` — шаги вопросов;
- `common/adapters.js` — вибратор, часы, JSON-файлы с чтением по 4 КБ, формат `%d/%s`;
- `pages/*` — 8 страниц: index, onboarding, setup, session, prompt, summary, history, settings.

## Подпись

Автоподпись DevEco для lite-часов не подходит: нужны сертификат и профиль из AppGallery Connect, в профиле должен быть UDID часов.

В AppGallery Connect → *Certificates, App IDs and Profiles* уже созданы:

- App ID `com.alekfletch.sedonabreath.lite` (проект Sedona Breath);
- устройство Huawei Watch Fit 4 Pro;
- debug-сертификат `SedonaLiteDebug`, действует до 13.10.2027;
- debug-профиль `SedonaLiteDebugProfile`.

Файлы подписи лежат в `lite/signing/` (папка в `.gitignore`): `sedonalite.p12`, `.csr`, `.cer`, `.p7b`, пароль в `signing.txt`. Рядом лежит `material/`: из него hvigor расшифровывает пароль, записанный в `build-profile.json5`.

**Подпись не попадёт в git.** Для `build-profile.json5` настроен clean-фильтр `tools/strip-signing.cjs`: при коммите `signingConfigs` превращается в `[]`. В новом клоне фильтр включается так:

```bash
git config filter.strip-signing.clean "node tools/strip-signing.cjs"
```

```bash
git config filter.strip-signing.smudge cat
```

```bash
git config filter.strip-signing.required true
```

На другом компьютере подпись можно прописать заново в DevEco: *File → Project Structure → Signing Configs*. Снимите *Automatically generate signature* и укажите `.p12`, пароль, alias `sedonalite`, `.cer` и `.p7b`.

## Установка на часы

Lite-часы не подключаются к DevEco напрямую. Подписанный HAP ставится **через телефон** приложением HUAWEI DevEco Assistant по Bluetooth.

1. **Телефон:** Android или Huawei с Huawei Health, часы подключены. Нужен HUAWEI DevEco Assistant из AppGallery.
2. **Часы:** *Настройки → О часах*, 5–7 раз нажмите на номер версии ПО, затем включите режим разработчика.
3. **Пакет:** `lite/out/SedonaBreathLite.hap` (копия `entry-default-signed.hap`).
4. **Перенос:** подключите телефон к ПК по USB в режиме передачи файлов. Создайте в корне памяти папку `haps` и скопируйте туда HAP.
5. **Установка:** DevEco Assistant → часы → *Install watch app* (или *Apps*) → выберите HAP.

Коды ошибок установщика (`appexecfwk_lite`):

- **26** — файл повреждён;
- **27–32** — подпись или профиль: UDID, bundle name, срок действия;
- **33** — версия JS-движка;
- **34** — не компилируется JS (например, RegExp);
- **40 и выше** — разбор `config.json` и иконки.

Для публикации в AppGallery нужны release-сертификат и release-профиль.

## Ограничения lite (проверить на часах)

- **Вибрация.** Есть только два системных шаблона, `short` и `long`. Три коротких тика в секунду на вдохе отправляются по таймерам JS; если тик `short` длиннее ~150 мс, удары сольются. Тогда в `VibrationPlanner.inhale` (ArkTS-ядро) уменьшите `perSecond` до 2 и перегенерируйте ядро. Длинный сигнал в конце длится около 1 с вместо 800 мс. Метода `stop()` у lite-вибратора нет: при паузе отменяются все будущие тики.
- **Переход между страницами сессии** занимает долю секунды. Шаг дыхания после вопроса начинается с нуля, время перехода в активное время не входит.
- **Время.** Монотонных часов в lite нет, используется `Date.now()`. Если перевести системное время во время практики, текущая фаза собьётся.
- **Жизненный цикл.** Пауза при выключении экрана срабатывает через `onHide`, если прошивка его вызывает, и через `onDestroy` страницы. Во время практики снимок дополнительно пишется каждые 5 с.
- **Вёрстка.** Размеры заданы в px под экран 408×480. Симулятор переносит строки по буквам, часы — по словам, поэтому на часах текст занимает больше строк. Где блоки обрезаются (длинные тексты онбординга, значения в «Итоге»), **проверить** на часах.
- **Нет:** Health Kit, карточек на циферблате, фоновой работы.
