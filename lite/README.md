# Sedona Breath Lite: Huawei Watch Fit 4 и Fit 4 Pro

Версия приложения для **lite wearable** — часов на LiteOS, которые запускают только JS-приложения (HML/CSS/JS, FA-модель). Это отдельный проект DevEco внутри репозитория: ArkTS-версия в корне на эти часы не устанавливается.

> Что модели Fit 4 и Fit 4 Pro относятся к lite wearable, известно с форума разработчиков Huawei и из сообщества; официального списка нет. **Проверьте** на своих часах: подключите их к DevEco и посмотрите тип устройства в Device Manager, должно быть `liteWearable`.

## Чем отличается от ArkTS-версии

| | ArkTS (корень репозитория) | Lite (эта папка) |
|---|---|---|
| Устройства | `wearable` (Watch 5, Ultimate…) | `liteWearable` (Watch Fit 4 / Fit 4 Pro и др.) |
| UI | ArkUI | HML + CSS + JS |
| Логика сессии | `entry/src/main/ets/core` | **та же**, сгенерирована в `core/*.js` |
| Строки | `resources/{base,en,es}` | **те же**, сгенерированы в `i18n/strings.js` |
| Вибрация | импульс 50 мс, длинный 800 мс | системные `short` и `long` (≈1 с); остановить уже идущую вибрацию нельзя |
| Хранение | Preferences + RelationalStore | JSON-файлы `internal://app/*.json` (`@system.file`) |
| Health Kit | пульс по согласию | нет |
| Быстрый старт 3 мин | карточка на часах | кнопка «Быстро · 3 мин» на главном экране (карточек на lite нет) |
| Язык | системный + ручной выбор | системный + ручной выбор, применяется сразу |

Экраны и сценарий те же (11 экранов): онбординг с дисклеймером → главный → настройка → вступление → дыхание и вопросы → выбор эмоции (полная практика) → завершающее дыхание → оценка 1–5 → сообщение → итог → «Сохранить». То же и с прерываниями: «Продолжить» / «Завершить сейчас» / «Завершить и сохранить», а после выгрузки процесса на главном экране «Практика не завершена».

## Единый источник правды

Ядро и строки **не редактируются вручную**: их генерирует `tools/build-lite.mjs` из ArkTS-проекта.

```bash
# пересобрать core/*.js и i18n/strings.js после изменений в entry/src/main/ets/core или в строках
node tools/build-lite.mjs
```

```bash
# проверить, что сгенерированные файлы актуальны (для CI)
node tools/build-lite.mjs --check
```

В `strings.js` попадают только ключи, которые встречаются в lite-страницах (`s.key` в `.hml` или строка-ключ в `.js`). Так словарь занимает меньше памяти: на lite-часах куча JS маленькая.

Вручную написаны:

- `app.js` — подключает модули `@system.*` и создаёт единственный `Services`. Каждая lite-страница — отдельный бандл, поэтому общее состояние доступно только через `this.$app.$def.services`.
- `common/adapters.js` — вибратор, часы и таймеры, JSON-файлы, выбор языка, форматирование `%d/%s`.
- `common/services.js` — настройки, история, снимок сессии (`SnapshotSink`), запуск, восстановление и сохранение сессий.
- `pages/*` — 7 страниц: index, onboarding, setup, session, summary, history, settings. Экраны 3–7 (дыхание, вопрос, эмоция, завершающее дыхание, оценка, сообщение) — это состояния страницы `session`.

## Сборка

```bash
cd lite
node "C:/Program Files/Huawei/DevEco Studio/tools/hvigor/bin/hvigorw.js" --mode module -p module=entry@default -p product=default -p buildMode=debug assembleHap --no-daemon
```

Результат: `entry/build/default/outputs/default/entry-default-unsigned.hap` и `bin/entry-default-unsigned.bin`. Проверено на DevEco 6.1.1 (шаблон `[Lite]Empty Ability`, `compatibleSdkVersion 4.0.0(10)`, `targetSdkVersion 6.1.1(24)`). Release-сборка (`-p buildMode=release`) тоже проходит.

В DevEco Studio откройте папку `lite/` как **отдельный проект**.

## Установка на часы

Подпись и отладка устроены так же, как в основной версии (см. [../docs/BUILD_AND_RUN.md](../docs/BUILD_AND_RUN.md)): HUAWEI ID в DevEco → *Project Structure → Signing Configs → Automatically generate signature* → часы в режиме разработчика с отладкой по Wi-Fi → *Run*. Пункты меню на lite-часах зависят от прошивки, **проверить**. Для публикации нужен release-сертификат и профиль из AppGallery Connect с устройством «Часы (lite)».

## Ограничения lite (проверить на часах)

- **Вибрация.** Есть только два системных шаблона: `short` и `long`. Три коротких тика в секунду на вдохе приходят по таймерам JS; если тик `short` на прошивке длиннее ~150 мс, удары сольются. Тогда в `VibrationPlanner.inhale` (ArkTS-ядро) уменьшите `perSecond` до 2 и перегенерируйте ядро. Длинный сигнал в конце длится около 1 с вместо 800 мс. Метода `stop()` у lite-вибратора нет: при паузе отменяются все будущие тики, а уже начавшийся короткий тик длится доли секунды сам.
- **Время.** Монотонных часов в lite нет, используется `Date.now()`. Если перевести системное время во время практики, текущая фаза собьётся.
- **Жизненный цикл.** Пауза при выключении экрана и уходе со страницы срабатывает через `onHide`, если прошивка его вызывает, и через `app.onDestroy`. Дополнительно во время дыхания каждые 5 с пишется снимок. Свайп вправо в сессии открывает диалог завершения; на остальных экранах работает как «Назад».
- **Шрифты и вёрстка.** На lite нет `vp/fp` и `font-weight`; размеры заданы в px (24/30/38) и в процентах ширины, а на длинных экранах используется `list`. Системный размер шрифта lite-UI не учитывает. Переносы длинных строк, высоту блоков и доступность размеров шрифта **проверить** на экране Fit 4 / Fit 4 Pro (прямоугольный AMOLED).
- **Нет:** Health Kit, карточек на циферблате, монотонного таймера, фоновой работы.
